## 一、用户四问答复

### Q1：电脑只在 13:00–17:00 开机，09:35 的成交任务怎么跑？——**策略调度有真问题，必须改**

**正面回答：按现在的设计，上午不开机就永远不会成交，这是 bug。**

现状：
- `QuantExecuteTask` 工作日 **09:35** 按开盘价执行成交（T+1 两段式）；
- `QuantDecideTask` 工作日 15:30 决策；
- 你的 Windows 只在工作日 **13:00–17:00** 开机。

后果：09:35 电脑关机，execute 任务**从不触发**；15:30 decide 能跑，但它算出的目标要等次日 09:35 执行——那时电脑又关着。**成交环节整段缺席。**

正确改法（待实施）：
1. **取消 09:35 固定成交任务**，不再做"T 日决策、T+1 开盘价成交"两段式。
2. 改为**开机即跑当日完整流水线**（开机触发、延迟约 3 分钟）：拉取当天行情 → decide → 立即按"开机时刻可得的最新价"撮合。
   - 13:00–15:00 盘中开机：用实时最新价成交；
   - 15:00 后开机：用当天收盘价成交。
3. akshare 下午本就能取到当天实时价/收盘价，不需要真的等 09:35。
4. 加"是否真实交易日"判断：节假日/周末本来就不开机；若假期调休日开机而当天无行情数据，则跳过不成交（避免空跑）。
5. 这样无论 13–17 点间几点开机，当天就完成决策+成交+上报，数据当天进 GitHub。

> 这是 P0 整改，10-07 实盘第一天前必须改完，否则第一天就没成交。

### Q2：数据要同步到"网页在线监控项目"

不需要另传第二个通道——**Mac 上的网页监控（`localhost:8000`）本来就是靠读 GitHub 数据仓库来显示 Windows 实盘的**：
Windows 成交后 `push` 到 `quant-monitor-live-data` → Mac 端 `pull` → 面板读本地 `live-data/`。GitHub 就是中转。
待办：确保 Mac 面板启动时和定时会 `pull` 最新数据（`scripts/sync_live_data.py` 的 pull 侧），这样你在网页上看到的就是 Windows 当天真实成交。

### Q3：10-06（国庆假期最后一天）17:00 全部清空归零，10-07 从零开始

### Q4：为什么改 Python、v9 为何成功、v1–v8 是否同因
详见根目录 `POSTMORTEM_Windows一键安装器八版失败_2026-10-04.md`。要点：v9 不是 JSON 是 Python（polyglot）；成功因为"Mac 可真机验证 + 全局异常捕获永不闪退 + 新文件名绕缓存 + 保留 SSH443"；v1–v8 失败**逐版不同**（编码→akshare卡死→UAC双开→22端口被封→缺git身份/锁残留→缓存旧版/cmd闪退），但同根于"用无法在Mac验证的cmd写复杂逻辑 + 连GitHub前物理静默"。
