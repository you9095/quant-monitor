# 2026-10-09 一键启动按钮失效修复：免管理员自动注册 + 遮罩全可点链接

## 现象（用户在 Windows 实测）
- 遮罩绿色「一键启动数据后台」点击无反应；「我已启动，重新连接」也无反应，始终停在“数据后台没有运行”。
- 遮罩里三处入口（启动器文件名、实盘网址、模拟网址）只是改了颜色的纯文字，不可点击。
- 用户最终靠手动复制 localhost:8000 才打开。

## 根因
1. quant:// 自定义协议上一版只在“管理员重跑 install_v9.bat/setup.py”时注册；用户没跑，协议在那台 Windows 未注册。未注册时浏览器对 quant:// 静默失败（file:// 下 location.href 对未知协议不弹窗、不跳转），按钮成摆设。
2. 旧“重新连接”只是 location.reload()，后台没起时刷新后仍是遮罩，看起来“没反应”。
3. 三处入口用的是 `<code>` 纯文本，不是 `<a>`。

## 修复（commit b25ffb3）
- 新增 `scripts/win_self_register.py`：仅 win32 生效，后端启动时自我注册
  - `reg add HKCU\Software\Classes\quant`（普通权限、无需管理员）绑定 `wscript.exe panel_guard.vbs "%1"`；
  - `schtasks /create /xml` 创建当前用户 QuantPanelGuard（LeastPrivilege、登录30秒+每5分钟），失败静默（仍有开机交易任务兜底起面板）；
  - 幂等、异常只写 logs/self_register.log，绝不阻断面板。
- `api/real_data_server_v2.py` 的 `__main__` 在 app.run 前调用 self_register_if_windows()。这样每天自动任务 git reset --hard 拉新代码、step_restart_panel 重启面板那一刻即自动完成注册，无需管理员、无需重跑安装器。
- index.html 遮罩：
  - 启动器文件、实盘网址、模拟网址全部改为 `<a class="ce-link">` 真链接（网址 target=_blank；启动器为同目录本地文件链接，浏览器可能改为下载，点下载项运行即可）；
  - 绿色按钮改用隐藏 iframe 触发 quant://（避免未知协议 location.href 卡死），随后每1.5秒轮询，30秒连上自动刷新，超时显示明确引导块；
  - “重新连接”改为 reconnectBackend()，带“正在重新连接…”文字与18秒轮询反馈。

## 边界（已如实告知用户）
- 浏览器安全沙箱禁止网页直接运行本机程序；quant:// 是唯一合规桥接，第一次仍需后端在本机启动过一次来完成注册——现在该注册随后端启动自动完成，免管理员。
- Windows 侧 reg/schtasks 无法在 Mac 实测；HKCU 注册普通权限确定可行，普通权限建 onlogon 任务若失败也不影响主路径（开机交易任务本就会重启面板）。
- 今天 10-09 下午 Windows 13:05/15:10 自动任务拉新代码重启面板即自动注册；之后按钮永久可用、开机后台自动在。
