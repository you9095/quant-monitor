## 一、持仓数据自相矛盾（黄金组合A / 闪电 / 追电）

### 现象
- 默认精简视图：策略卡显示"持仓 1 只"；点击展开详情：显示"无持仓"。
- 卡片右上角动作标签显示"持有/调仓"，左侧却显示无持仓，左右矛盾。闪电、追电、黄金组合A 均如此。

### 三条数据线先厘清（避免改错地方）
1. 策略卡主数据：`/api/v1/dashboard/overview` → `assets/data.js` 的 `transformApiData`，字段 `s.holdings`，子字段 `qty`（API 的 `quantity` 映射而来）。
2. 动作标签：`/api/v1/dashboard/today_actions_all`。
3. `/api/v1/strategies` 的 holdings 全空，**不是渲染源**，别被带偏。

实测 overview 真实持仓：仅 qixing(511880,1000)、r32(512040,920)、sanhe(5只) 有真实持仓；zhuidian/lightning/goldcombo 的 holdings 为空数组。

### 两个根因
- **根因 A（计数错误）**：无持仓时 `buildCardHtml` 生成 `<div class="holding-row">无持仓</div>` 占位行；而 `enhanceCardsForResponsive` 用 `card.querySelectorAll('.holding-row').length` 数持仓，把占位行也数成"1 只"。
- **根因 B（动作默认值错误）**：动作缺失时默认 `'HOLD'（持有）`，空仓也显示"持有"，与"无持仓"自相矛盾。

### 修复
1. 占位行 class 从 `holding-row` 改为 `holding-empty`，使其不被持仓计数选中。
2. 新增统一有效持仓判定，过滤 qty=0 的零持仓占位：
   ```js
   validHoldings = holdings.filter(h => (h.qty!=null && h.qty>0) || (h.weight!=null && parseFloat(h.weight)>0));
   hasPosition = validHoldings.length > 0;
   ```
3. 空仓且动作属于 HOLD/REBALANCE/DEFENSIVE 时，统一校正为 **FLAT(空仓)**；新增 `.action-badge.flat`、`.tas-action.FLAT` 灰色样式，中文映射加 `FLAT:空仓`，动作流程文案加"空仓观望"。
4. `buildCardHtml`、`renderActionItems`、`renderTradeDetails` 三处渲染统一改用 validHoldings + FLAT 校正。

## 二、收益对比"检测到 8 个数据突变点"误报根治

### 排查过程（用原始 work_logs 取证，不臆测）
后端 `api/live_data.py` 的 `_build_curve_from_signal_snapshots`：每个日期取 `(date, cum_amount, capital)`，计算
- `values = actual_cap + cum_amount`（市值金额）
- `returns = cum_amount / actual_cap * 100`（累计收益率，**图表实际绘制的就是它**）

查 `~/.hermes/work_logs/lightning/` 原始 JSON：
- 2026-06-08：capital=100000，cumulative=57301.7 → returns 57.3%
- 2026-06-25：capital=100000，cumulative=61480.7 → returns 61.48%
- 2026-06-26：**capital 切回 10000**，cumulative=6125.8 → returns 61.26%
  - 这一天 values 从 161480 掉到 16125（约 10 倍跳变），但 returns 61.48%→61.26% 基本连续。

### 根因
**前端异常检测遍历的是 values（市值），相邻变化率 >30% 就报异常；可图表画的是 returns。** values 在账户本金口径切换（10 万↔1 万）时必然约 10 倍跳变，于是把正常的本金切换误报成"突变点"，共 8 个。属于"检测字段与绘制字段不一致"的明确 bug。

### 为什么不能"平移桥接抹平"
试过把 returns 序列在跳变点整体平移消阶，但会改变终值：lightning 35.77%→14.17%、zhuidian 146.26%→23.10%，与策略卡 overview 的 total_return 直接矛盾。**真实每日盈亏不允许编造抹平，此方案否决。**

### 最终修复（前端，不改真实数据）
1. **检测字段改 returns**（与绘制字段一致），跳过 null，阈值改为"单日累计收益率变动 >40 个百分点"（正常策略单日不可能超 40pp）。
2. **消除起始假阶跃**：6-08 是首个真实 work_log（之前后端补 0、`is_interpolated=true`），X 轴截断到 6-06 后，"补 0→首个真实值"形成 0→57% 的假阶跃。用 `is_interpolated` 把"首个真实点(false)之前"的 returns/values 置 null，曲线从首个真实点起画。
3. 警告文案从吓人的"⚠️检测到 N 个突变点"改为中性的"ℹ️ X 历史上调整过账户本金/累计口径（真实每日盈亏正常，非数据错误）"，并把 sid 映射中文名。
4. 顺手修了同源的数据源标签遗漏：goldcombo 的 `data_source=goldcombo_real_backtest_evidence`（cross_check PASS 的真实回测净值）既非 work_logs 也非 signal_fallback，旧判定把它误显示成"❓数据源未知"。改为 evidence 也算真实源，现显示"✓ 5 策略实盘模拟真实日 P&L + 1 策略真实回测净值 · 113 天"。

### 结果
40pp 阈值 + 起始 null 处理后，剩余突变点 = **0**，警告消失，曲线连续，且终值与策略卡一致（未改任何真实数据）。

## 三、参数稳定性监控板块移动端适配

### 根因
容器 `#param-stability-cards` 在 HTML 里写了**内联** `style="display:grid;grid-template-columns:repeat(5,1fr)"`。内联样式优先级高于 `@media` 媒体查询，导致手机端 5 列硬挤在 316px 里，每列约 50px，评分/分布柱状图全部挤爆——这正是"迭代很多版却一直没适配"的原因：媒体查询根本覆盖不了内联样式。

### 修复
- `@media(max-width:768px)`：`#param-stability-cards{grid-template-columns:1fr !important}`（卡片内容多，单列最清晰），卡片内边距/圆角收紧。
- `@media(769-1024px)`：2 列。
- 桌面端保持 5 列（1400px 实测仍 5 列，未破坏）。
- 顺带修正标题/meta 写死的"4 策略"——qixing 2026-07-04 加入后实为 5 张卡，标题改"5 策略"，meta 改为 `Object.keys(strategies).length` 动态统计，避免再次失配。

## 五、策略卡顶部彩色条偏移修复

### 根因（从项目初期就存在）
`.strategy-card` 是 `display:flex;flex-direction:column` + `border-radius` + `overflow:hidden`，`.card-header`(高 4px) 是第一个子元素，桌面端无 padding，本应贴边。但手机端媒体查询 `@media(max-width:767px)` 写了 `.strategy-card{padding:var(--space-md)}`（16px）——**padding 加在整张卡上，把内部彩色条向内向右各顶进 16px、向下顶 16px**，于是彩色条看起来"悬浮在卡片中间、偏移几像素"。

### 修复
- 手机端 `.strategy-card{padding:0}`，把内边距只加到内容区 `.strategy-card .card-body{padding:var(--space-md)}`。
- `.card-header` 显式 `width:100%;flex-shrink:0;margin:0;padding:0`，在 flex column 下防压缩、严格对齐。
- 316px 实测：card-header 左边与卡片左边 gap≈0（仅 1px border），宽度=卡片宽-左右 border，完美贴合。
- 顺带补上遗漏的颜色同步：`.card-header.zhuidian` 从旧橙 `#f97316` 改为全局灰 `#94a3b8`。

## 八、核心教训（沉淀到 Skill）

1. **检测字段必须与绘制字段一致**：图画 returns 就不能用 values 做异常检测，口径切换会造成必然误报。
2. **占位元素不能复用真实元素的 class**：否则任何 `querySelectorAll` 计数都会把占位算进去（无持仓被数成 1 只）。
3. **内联样式优先级高于媒体查询**：HTML 内联 grid 必须用 `!important` 才能在移动端覆盖，这是"反复适配却不生效"的常见隐藏根因。
4. **容器 padding 会顶偏内部贴边装饰条**：卡片顶部彩色条/色带要贴边，padding 只能加在内容区 body，不能加在最外层卡片。
5. **真实数据不许为了好看而抹平**：平移桥接会改终值、与其他板块矛盾，宁可保留真实口径断点 + 准确说明。
6. **排查手机端布局先用 scrollWidth 对比 innerWidth**：水平溢出会把整页撑宽、内容挤左，极易被误判成"缓存/样式没更新"。
