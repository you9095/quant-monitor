## 一、第一轮：3 项基础优化

### 1.1 删除策略卡顶部"买入规则"标签

**现象**：策略卡顶部 three-layer-tags 区域有 4 个标签，第 3 个 `tlt-caliber`（`s.metrics.caliber`）显示"买入规则: breadth 大于等于 0.353"等内容，与第 4 个详情标签（`config_caliber_full`）内容重复，用户确认多余。

### 1.2 默认隐藏策略卡底部持仓和仓位信息

**现象**：移动端默认状态下策略卡底部显示完整持仓表格（标的/权重/成本/盈亏）和"仓位/现金"指标，信息冗余、空间浪费。

### 1.3 布局空间优化

## 二、第二轮：7 项深度优化

### 2.1 顶部栏重构为两行

**现象**：原顶部栏为单行 flex 布局，左边标题、右边 topbar-meta（时间+4属性+刷新按钮挤在一起），用户要求时间移到右上角与标题同行，4属性与刷新按钮同行。

**修改**：

  - `.topbar-row-main`：`.topbar-brand`（标题，左）+ `.topbar-time`（日期+时间，右）

- 移动端适配：`.topbar-time` 字号 11px；`#current-date` 仍隐藏（只显示时间节省空间）；`.topbar-row-sub` align-items:flex-start。

### 2.6 展开后文字颜色统一（含 compact-summary 两个 bug 修复）

**现象**：点击展开后，compact-summary 里"持仓"和"交易"的值颜色明显比其他字亮（font-weight:600 + 默认 text-primary），且"交易"行错误显示"当前市值¥12,034.00"而非交易笔数。

**两个根因**：
- **根因 A（内联样式语法错误）**：`compact.style.cssText = 'margin-top:var(var(--space-sm))padding:var(--space-sm)background:...'` — 属性之间缺分号，且 `var(var(--space-sm))` 嵌套错误，导致整条样式静默失效。

**修改**：
- 废弃内联样式，改用 CSS 类 `.compact-summary` 统一控制
- 交易数据改从 `.card-footer-cash` 取（`交易 144 笔`）
- CSS 规范：`.cs-label { color:var(--text-muted); font-size:11px; text-transform:uppercase; letter-spacing:0.5px }`；`.cs-value { color:var(--text-secondary); font-size:12px; font-weight:500 }`
- 容器样式：`margin-top:var(--space-sm); padding:var(--space-sm) var(--space-md); background:rgba(255,255,255,0.03); border-radius:var(--radius-sm); border:1px solid var(--border-subtle)`

## 三、关键踩坑与经验

### 3.1 compact-only 与 full-only 类同时使用时 CSS 冲突

**问题**：给 compact-summary 同时加 `compact-only full-only` 两个类，期望移动端默认隐藏。但移动端 @media 里 `.compact-only { display:block }`（224行）在 `.full-only { display:none }`（223行）之后定义，同优先级下后定义胜出，导致元素仍显示。

**解决**：用独立类 `.compact-summary`，不依赖 full-only/compact-only 的组合。独立定义 `.strategy-card .compact-summary { display:none }` 和 `.strategy-card.is-expanded .compact-summary { display:block }`。

### 3.2 动态生成 DOM 的内联样式缺分号会静默失效

`compact.style.cssText = 'margin-top:var(var(--space-sm))padding:var(--space-sm)background:...'` — 属性间缺分号导致整条 cssText 解析失败，样式完全不生效，且不报错。应优先用 CSS 类而非内联 style。

### 3.3 动态摘要取数据时要确认数据源

`pb-meta-item:last-child` 取到的是"当前市值"而非"交易笔数"，因为 pb-meta-item 有两个元素（收益率、当前市值）。取数据前应先确认目标元素的数量和顺序，交易笔数应从 `.card-footer-cash` 取。

### 3.4 标签样式应定义一套基础规范，其他场景复用

`.action-badge`（收益曲线板块）和 `.tas-action`（策略卡今日流程）原本各定义一套样式，导致圆角/字号/字重不一致。应定义一套基础规范（.action-badge），其他场景复用或对齐，避免视觉碎片化。
