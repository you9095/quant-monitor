## 第一轮：4 个问题（答疑 + 修复）

### Q1：样本外 OOS 累计板块的功能是什么？

**解答**：该板块属于 WFA 过拟合审计的一部分，展示 4 个策略在 13 个滚动测试窗口上的**样本外（Out-of-Sample）累计收益**。

- **能读到的信息**：每条曲线代表一个策略在逐窗口滚动测试中的累计收益走势；曲线持续上升说明该策略参数在新数据上仍有效，曲线走平或下降说明可能过拟合。
- **对策略的帮助**：检测过拟合——如果一个策略在训练集（样本内）表现好但 OOS 表现差，说明参数是过拟合出来的，实盘大概率失效。OOS 是判断策略是否"真有效"的核心证据。

### Q2：参数稳定性监控为什么只有 4 个？是 4 个指标吗？

**解答**：不是 4 个指标，是 **4 张策略卡片**。

- 每张卡片对应一个策略（追电/三合/闪电/三驾马车），监控该策略的**一个核心参数**在 13 个训练窗口上的分布稳定性。
- 例如追电策略监控 `SCORE_MAX`，三合策略监控 `BREADTH_THRESHOLD`。
- 卡片内展示：稳定性评分（1.00=非常稳定）、当前值 vs 众数、13 窗口参数分布直方图、std 和中位数。
- 用户的理解"一个策略需要一个监控指标"基本正确——确实是一策略一参数，但目前只覆盖了 4 个策略（七星和黄金组合A 尚未纳入）。

### Q3：AB 对照数据失真（两个值为 0）—— Bug 修复

**现象**：AB 对照 KPI 显示 grid_wins=0, baseline_wins=0, ties=4，与历史观察严重不符。

**根因**：后端 `api/real_data_server_v2.py` 第 1233 行和第 1261 行读取 winner 字段的路径错误：

```python
# 错误代码（两处）
winner = data.get('diff', {}).get('winner')

# 正确代码
winner = data.get('winner')
```

`winner` 字段实际在策略对象的顶层，不在 `diff` 子对象中。路径错误导致所有策略的 winner 都返回 `None`，被误判为 ties。

**修复后结果**：grid_wins=4, baseline_wins=0, ties=0，4 策略全部 grid_mode 胜出，与历史数据一致。

**教训**：后端数据 bug 要追溯到字段路径，不能只看表面现象。JSON 嵌套结构的字段路径是常见出错点。

### Q4：收益曲线板块移至顶部 + 高度固定（初次实现有误）

- 将"收益曲线·实盘模拟"板块从页面中部移至最顶部。

## 关键经验教训

### 1. 理解用户需求时要特别注意范围限定
用户说"400px"时，要确认是**哪个板块**的 400px、是**整个板块**还是**每一行**。初次实现时把 400px 全局化导致所有策略卡片被压缩，后被用户纠正。**范围限定词是硬约束，不能泛化。**

### 2. CSS 类名与显示文字分离
中文化时，CSS 类名（如 `.tas-action.HOLD`）必须保持英文，因为样式表用英文类名选择器；只有用户可见的显示文字需要翻译。在 `renderLogs` 中用 `actionClass`（英文，用于 CSS）和 `action`（中文，用于显示）两个字段分离。

### 3. 后端数据 bug 要追溯到字段路径
AB 对照 KPI 全 0 的根因是 JSON 字段路径错误（`data.get('diff', {}).get('winner')` vs `data.get('winner')`）。表面现象是"数据失真"，实际是代码读取了不存在的路径。**遇到数据异常，先打印原始 JSON 结构，再核对读取路径。**

### 4. 颜色全局统一是系统性规则
每个策略的颜色在整个项目中必须固定。修改一个策略颜色后，需要同步更新所有板块（策略卡片、收益曲线、OOS、收益对比、Daily P&L、AB 对照、策略变更日志）。OOS 板块之前使用 API 返回的自定义颜色，导致与全局不一致，必须强制覆盖。

### 5. X 轴截断是常见的数据可视化优化
用户多次要求"X 轴从某日期开始，前面的删除"。实现方式：在图表渲染前对数据数组按日期过滤，只保留 >= 截止日期的数据点。注意 Daily P&L 需要同时增加获取天数（从 14 到 60），否则截断后数据点不足。

### 6. 服务重启后端口可能处于 CLOSED 状态
多次重启服务时，端口 8000 上的进程可能处于 `CLOSED` 状态，普通 `kill` 无法释放，需要 `kill -9`。`start.sh` 会检查端口占用并报错，遇到 CLOSED 状态进程时需强制杀死。

### 7. localhost 在远程设备上永远指向设备本身
排查手机访问问题时，第一反应应该是"localhost 指向谁"。在远程设备（手机/另一台电脑）上，localhost 永远是那台设备自己，不是服务器。正确做法是用服务器的局域网 IP 或 Tailscale IP。
