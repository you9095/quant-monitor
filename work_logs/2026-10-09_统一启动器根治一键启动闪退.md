# 2026-10-09 统一启动器 launch_panel.py：根治一键启动“黑窗一闪即退”

## 现象
用户在 Windows 点绿色「一键启动数据后台」，有一个窗口闪现不到 0.1 秒就关闭，后台未起、页面停在遮罩；方案 A/B 均无效。

## 根因（比上一版判断更深一层）
- 窗口能闪现，说明 quant:// 协议其实已被系统识别并调起了处理程序；
- 旧链路是 浏览器 quant:// → wscript panel_guard.vbs → start_panel_quiet.bat → venv python run_simulation.py，共 4 跳；
- 最后一跳启动后端时立即报错退出，而 VBS 以 0（隐藏窗口）、bat 以 start /min 运行，错误被隐藏窗口吞没，没有日志、没有弹窗，用户只看到“一闪”。
- 教训：跨进程隐藏启动链一旦失败必须可观测（日志 + 可见弹窗），否则无法远程诊断。

## 方案：所有入口汇聚到一个统一启动器
新增 `scripts/launch_panel.py`，quant:// 协议、QuantPanelGuard 计划任务、启动器 .bat/.command 全部调它：
- 幂等：先 GET /api/v1/health，已在运行直接退出；
- 未运行：用同目录 python.exe 以 DETACHED + CREATE_NO_WINDOW（无黑窗）拉起 api/real_data_server_v2.py（-u），stdout/stderr 全部追加 logs/backend_boot.log；
- 轮询健康端点最多 90 秒，就绪退出码 0；超时/启动异常在 Windows 用 ctypes MessageBoxW 弹明确错误框并指向日志，绝不静默；
- 文件锁 logs/launch_panel.lock（msvcrt/fcntl），防止按钮点击与 5 分钟计划任务并发拉起多个后端。

配套改动：
- win_self_register.py：quant 协议与 QuantPanelGuard 直接绑定 `pythonw.exe launch_panel.py`（最短路径，不经 VBS/bat）；支持 highest 参数（安装器管理员版 HighestAvailable，后端运行时普通权限 LeastPrivilege）。
- setup.py 第 5 步删除内联 reg/XML，改为 import win_self_register 并 highest=True，单一真相。
- start_panel_quiet.bat / panel_guard.vbs / 启动AI量化面板.command 全部改为调用 launch_panel.py（VBS 仅作旧注册残留的后备）。
- index.html：一键启动前端轮询 30s→60s（首次要同步数据），文案同步。

## 验证（Mac）
- py_compile 全过；Mac 上 self_register_if_windows() 返回 False；bat/vbs 纯 ASCII。
- 端到端：launchctl bootout + kill 彻底停后端 → 运行 api/venv/bin/python scripts/launch_panel.py
  输出“数据后台未运行，正在启动…”→ spawn real_data_server → “数据后台已就绪”，exit=0，
  随后 curl /api/v1/health=200；logs/backend_boot.log 完整记录启动全过程。
- 截图脚本 trap 一度未把 launchd 重新接管（8000 空），已手动 bootout+bootstrap+kickstart 恢复，
  最终 launchctl list 显示 ai.quant.flask PID 在跑、health=200。
- 遮罩截图 references/verify-2026-10-09-one-click-fix/ 复核三链接正常。

## Windows 生效路径与未覆盖项
- Windows 拉到新代码（每日 git reset --hard，或手动 fetch+reset）后，需后端重启一次：
  重启时 real_data_server __main__ 调 win_self_register，把 quant 协议改绑到 pythonw launch_panel.py；
  此后点绿色按钮无黑窗、失败有弹窗，日志在 D:\quant-monitor\logs\backend_boot.log。
- Windows 上 pythonw/计划任务的实际行为无法在 Mac 真机验证；已保证：失败必有弹窗+日志、
  开机交易任务 step_restart_panel 仍会起面板作为兜底。
