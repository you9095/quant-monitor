## 二、#49 双击 index.html 直接打开面板（b21b5a5）

### 根因（四层）
1. index.html 是纯前端门面，数据全靠 fetch 本机 Flask:8000；双击走 `file://`，**不会启动后台**。
2. 前端 apiBase 是根相对 `/api/v1`，file:// 下被解析成 `file:///api/v1`，必然失败。
3. #44 之前失败会静默回退写死 mockData（8 月假盈亏）；#44 删除回退后显示"未连接"遮罩。
4. 浏览器安全沙箱禁止网页（file://）启动本机进程，故后台没运行时 HTML 无法自拉起，必须配系统级启动器。

### 改动
- index.html `<head>` 最前注入 `QM_IS_FILE` / `QM_ORIGIN`；`window.apiUrl` 在 file:// 下把 `/api` 补成 `http://localhost:8000`。
- assets/data.js、data_v2.js 的 `apiBase`、common.js 的 `API_BASE` 按 file:// 动态绝对化；修复 index.html 一处裸 `fetch('/api/v1/strategies')`。
- 后端本就有 CORS `Access-Control-Allow-Origin: *`，file://（null origin）简单 GET 可过——首页/子页面 file:// 实测直接渲染真实数据。
- 未连接遮罩改为引导"双击一键启动文件"，按 Mac/Windows 显示对应文件名。
- 新增 Mac `启动AI量化面板.command`（chmod+x；检测 8000→launchctl kickstart ai.quant.flask→第5秒 nohup 兜底→open 实盘页）；Windows `启动AI量化面板.bat`（**纯 ASCII**，netstat 检端口→start /min venv python run_simulation.py→轮询30秒→开浏览器，避开 V1–V8 中文编码闪退坑）。

### 结论（两种双击入口）
- 后台在跑（Mac launchd 常驻 / Windows 交易日开机 step_restart_panel）：**双击 index.html 直接进**。
- 后台没跑：双击 `启动AI量化面板.command`（Mac）/ `启动AI量化面板.bat`（Win），自动起后台+开页面。均无需敲 URL。
- 验证截图：references/verify-2026-10-08-file-open/01_index_file_live.png、02_trades_file_live.png。

## 三、#50 跨日红灯锁定（287e45c）

### 问题
旧逻辑 17:00 失败只写当日 trade_health.json=pending_overnight；次日监督器不读旧红灯，行情恢复成交成功即用 done 覆盖，红灯自动熄灭——违背"红灯跨日持续、不自动补单"。

### 设计：持久红标 trade_redflag.json
- 新模块 `api/trade_redflag.py`：`raise_redflag / load_redflag(只认未ack) / is_active / acknowledge`。红标独立于每日被覆盖的 trade_health.json，放在 `live-data/_run_logs/trade_redflag.json`，经数据仓库 GitHub 同步到 Mac。
- **监督器 trade_supervisor 最前置闸门**（acquire_lock 后、交易日/窗口判断之前）：只要有未解除红标，任何一天（含周末/节假日）都不判断窗口、不跑 attempt_round、不补单，恒写红灯心跳并 push，退出码 2。
- 17:00 极端失败：除当日红灯心跳外，`raise_redflag` 落持久红标。
- **引擎纵深防御** run_daily_engine.main：once/decide/execute/both 在红标锁定时一律退出码 3，杜绝绕过监督器补单。
- **聚合层 live_aggregator.build_trade_health 红标优先**：哪怕当日心跳是 done/no_trade_day/无心跳，只要红标未解除就强制 status=pending_overnight、redflag_active=true、held_over，面板恒红。
- 前端 tradeHealthTxt：红灯文案改"红灯持续中（事故日X，已跨日持续）：已停止自动成交/补单，须人工核对后解除"，删除"待补单"；新增 redflag_acknowledged 解除态中性提示。
- **人工解除（唯一出口）**：`python scripts/ack_trade_redflag.py`（Mac/Windows 通用，置 acknowledged 留痕 + 写解除心跳 + push 同步灭灯）；监督器另提供 `--ack-redflag` / `--redflag-status`。解除后从下一交易窗口恢复自动成交，**被冻结日不补**。

### 测试
- 新增 tests/test_trade_redflag_lock.py **17 项全 PASS**：A 红标次日/周末冻结不成交无落盘；B 红标优先于 done 恒红；D 引擎 once 退出码3；C ack 后恢复真实价成交。
- 原 tests/test_trade_supervisor_fault_injection.py **11 项无回归全 PASS**。
- 隔离截图（QM_LIVE_DATA_DIR + PORT=8011 复制账本注入红标，不碰真实 live-data）：references/verify-2026-10-08-redflag/redflag_persist.png，红色横幅"🔴 红灯持续中（事故日 2026-10-07，已跨日持续）：已停止自动成交/补单，须人工核对后解除"。截毕关停 8011、删除临时目录，确认真实 live-data 无 trade_redflag.json 残留。
