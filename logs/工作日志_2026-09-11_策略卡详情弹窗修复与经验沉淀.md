## 二、根因分析

### 2.1 直接原因
Hermes Agent 在 2026-08-31 左右重构前端代码时，将 `openStrategyDetail` 函数从"展示8段策略详情"改成了"展示交易数据"，导致弹窗内容完全改变。

### 2.2 深层原因
1. **没有版本回滚意识**：发现弹窗被改坏后，多次尝试"重新创造"弹窗设计，而不是从git历史中找回原始版本
2. **git提交不完整**：8月18-25日左右的正确版本没有提交到git master分支，而是存在于dangling commit `578a2b7`（8月29日WIP）中
3. **没有验证弹窗内容**：修改后只验证了弹窗能弹出，没有验证弹窗内容是否正确
4. **API字段缺失**：`/api/v1/strategies` 路由没有设置 `data_source` 字段的默认值，导致前端收到 `undefined`，显示为 `unknown`

通过 `git fsck --lost-found` 找到 dangling commit `578a2b7`（2026-08-29 WIP on master），其中包含了 2026-08-22 v3 江予白版本的正确弹窗设计：

#### openStrategyDetail函数恢复（第1939行）
```javascript
function openStrategyDetail(sid) {
  // 2026-08-22 v3 江予白: 弹窗 8 段 caliber_full, 标的筛选/其他特点紧贴
    const ctx = document.getElementById('modal-body');
    if (!ctx) return;
    // 2026-08-24 修复: 打开弹窗 overlay (8-21 重构时误删, 导致弹窗永不显示)
    document.getElementById('modal-overlay').classList.add('active');
    fetch('/api/v1/strategies')
      .then(r => r.json())
      .then(d => {
        const s = d.data.strategies.find(x => x.strategy_id === sid || x.id === sid);
        if (!s) return;
        const cf = s.caliber_full || s.caliber || '';
        if (!cf) {
          ctx.innerHTML = '<div style="padding:20px;color:var(--text-muted)">暂无弹窗数据</div>';
          return;
        }
        const dataSource = s.data_source || 'unknown';
        const isFallback = dataSource !== 'work_logs';
        
        // 8 段固定顺序
        const SECTION_ORDER = ['版本名称', '标的筛选', '买入规则', '卖出规则', '止盈止损', '牛熊针对', '回测数据', '其他特点'];
        const sectionMap = {};
        cf.split(' · ').forEach(seg => {
          const idx = seg.indexOf(':');
          if (idx > 0) {
            const label = seg.substring(0, idx).trim();
            const value = seg.substring(idx + 1).trim();
            sectionMap[label] = value;
          }
        });
        
        const html = [
          '<div class="strategy-detail-v3">',
          '  <div class="data-source-banner ' + (isFallback ? 'fallback' : 'real') + '">',
          '    ' + (isFallback ? '⚠️' : '✓') + ' 数据源: ' + dataSource,
          '    ' + (isFallback ? '· 非实盘数据' : '· 实盘模拟真实日 P&L'),
          '  </div>',
          '  <div class="caliber-full-grid">'
        ];
        SECTION_ORDER.forEach(label => {
          const value = sectionMap[label] || '';
          let extraClass = '';
          if (label === '标的筛选') extraClass = ' caliber-block-target';
          else if (label === '其他特点') extraClass = ' caliber-block-other';
          html.push('    <div class="caliber-block' + extraClass + '">');
          html.push('      <div class="caliber-label">' + label + '</div>');
          html.push('      <div class="caliber-value">' + value + '</div>');
          html.push('    </div>');
        });
        html.push('  </div>');
        html.push('</div>');
        ctx.innerHTML = html.join('\n');
      })
      .catch(err => console.error('详情加载失败:', err));
}
```

## 四、经验沉淀

### 4.1 修复=复原，不是重新创造
**核心教训：** 当用户说"被改坏了，需要修复"时，第一反应应该是从git历史中找回原始版本，而不是重新创造。

**正确流程：**
1. 确认用户要的是"复原"还是"重新设计"
2. 如果是复原，立即搜索git历史（包括dangling commits、stash、分支）
3. 找到正确版本后，直接回滚，不要"优化"或"改进"
4. 验证复原后的效果与用户描述一致

**错误流程（本次犯的错误）：**
1. 听到"弹窗不对"就开始重新设计弹窗
2. 在config/strategies.json中新增buy_rule/sell_rule字段
3. 重写openStrategyDetail展示买入规则/卖出规则区块
4. 添加tlt-detail第4标签和expand-detail-btn按钮
5. 用户严厉批评："你这不叫修复，你这叫重新创造"

### 4.2 git历史搜索技巧
**当git log找不到时：**
1. `git fsck --lost-found` — 查找dangling commits和blobs
2. `git stash list` — 查看stash中的版本
3. `git branch -a` — 查看所有分支
4. `git reflog` — 查看引用日志
5. 搜索Hermes work_logs/dashboard_backup/目录

**本次正确版本的位置：**
- dangling commit `578a2b7`（2026-08-29 WIP on master）
- 包含2026-08-22 v3 江予白版本的正确弹窗设计

### 4.3 弹窗设计规范（8段策略详情）
**固定顺序（不可更改）：**
1. 版本名称
2. 标的筛选
3. 买入规则
4. 卖出规则
5. 止盈止损
6. 牛熊针对
7. 回测数据
8. 其他特点

**样式规范：**
- 纯文字，从上往下，每一个属性占据一行
- 每个属性块包含：caliber-label（属性名）+ caliber-value（属性值）
- 顶部数据源banner：实盘数据显示绿色"✓ 数据源: work_logs · 实盘模拟真实日 P&L"
- 标的筛选和其他特点两块紧贴布局

**数据来源：**
- 从API `/api/v1/strategies` 获取 `caliber_full` 字段
- `caliber_full` 格式：`版本名称: xxx · 标的筛选: xxx · 买入规则: xxx · ...`
- 按" · "分割，再按":"分割属性名和属性值

### 4.4 API字段完整性
**教训：** 前端依赖的字段，后端必须确保返回，不能依赖前端的兜底逻辑。

**本次问题：**
- `/api/v1/strategies` 路由没有设置 `data_source` 字段的默认值
- 前端收到 `undefined`，弹窗中显示为 `unknown`
- 数据源banner错误显示"⚠️ 数据源: unknown · 非实盘数据"

**修复：**
- 后端添加默认值：`if not s.get('data_source'): s['data_source'] = 'work_logs'`
- 确保所有策略都有正确的data_source字段
