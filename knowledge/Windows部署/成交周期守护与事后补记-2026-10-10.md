# 成交周期守护（QuantTradeGuard）与事后补记 · 2026-10-10

> 适用：A股 ETF 多策略，6 策略各 1 万本金，Windows `D:\quant-monitor` 本机真实撮合，**不接任何券商账号**。
> Mac 设计制作、Windows 交易日下午开机实盘运行、GitHub 中转。

## 一、为什么从"长驻监督器"改成"周期守护"

2026-10-09（周五，第二个交易日）用户下午全程开机，但当天零成交、零心跳。硬证据：数据仓库 `daily/`、`_run_logs/` 只有 10-08，10-09 交易时段没有任何 trade_health 提交——说明不是引擎成交失败，而是 **13:05/15:10 计划任务根本没把监督器跑起来**。

旧方案的结构性弱点：
- `schtasks /sc weekly /st 13:05|15:10` 未设 StartWhenAvailable，错过不补；锁屏/登录界面默认不触发；
- 只有 onlogon + 13:05 + 15:10 三个稀疏触发点；onlogon 上午登录后监督器最多等到约 11:23 就退出，下午不重新登录就不再触发；
- update_code/pip 之前不上报"已触发"心跳，Mac 无法区分没触发还是触发即崩；
- 旧监督器 17:00 一刀切落红标（该规则已被用户否定，见下）。

**新方案：高频幂等周期守护。** 计划任务每 10 分钟唤醒一次 `trade_supervisor.py --guard`，每次只跑一轮就退出；非交易日 / 已成交 / 红标 / 上午都秒退，真正成交只在交易日下午，不是 7×24 常驻。周期重复天然实现"每 10 分钟持续重试"。

## 二、成交规则（2026-10-10 用户权威更正）

- **唯一不成交条件：东财→腾讯→新浪三源真实价全部失败。**
- 拿得到当日真实价（盘中实时 / 收盘后收盘价）就成交；15:00 收盘后现价即收盘价，下午傍晚都能补当日，**没有 17 点截止**。
- 失败每约 10 分钟持续重试到成功，绝不用旧价、绝不伪造。
- 跨日漏单：取得到漏单日真实收盘价就自动补记、标"事后补记"；连历史收盘价都三源全失败才红灯常亮等人工。
- 旧档里"17:00 后绝不自动补单 / 跨日冻结一切"是误固化，已更正，旧档保留可追溯。

## 三、guard_once 判定顺序

1. 单实例锁（supervisor.lock，新鲜阈值 14 分钟）。
2. 每天首次触发：push `guard_triggered` 心跳（最早期可观测）。
3. 红标 active → 维持红灯、秒退（return 2）。
4. **跨日补记**：找"首个已成交日之后、今天之前"缺失的交易日，升序调 `backfill_day.backfill_one`，标事后补记；rc=4/5（历史真实价三源全失败）才落红标，rc=3（乱序保护）只跳过不亮灯。
5. 今天非交易日 → no_trade_day 秒退。
6. 今天已六策略齐全 → done 秒退。
7. 交易日上午(<13:00) → waiting_afternoon 秒退（不抢跑）。
8. 交易日 ≥13:00 未成交 → attempt_round 取真实价撮合：全成 done+push；缺价写 retrying（next_retry +10 分钟）+push、return 0，等下一次守护；当天没成，次日第 4 步自动补。

## 四、Windows 计划任务 QuantTradeGuard（XML）

注册函数：`scripts/win_self_register.py::_register_trade_guard_task`，由 `self_register_if_windows()` 调用，而后端 `api/real_data_server_v2.py` 启动时会自动调它——**Windows 开机/双击图标把后端拉起来一次，任务就自动注册/更新，无需重跑安装器**。

- 触发器：LogonTrigger 延迟 PT2M + Repetition PT10M/Duration P1D；CalendarTrigger 周一–周五 当年起 13:00 + Repetition PT10M/Duration PT10H。
- Settings：StartWhenAvailable=true、DisallowStartIfOnBatteries=false、StopIfGoingOnBatteries=false、RestartOnFailure(PT2M×3)、MultipleInstancesPolicy=IgnoreNew、ExecutionTimeLimit=PT15M、RunOnlyIfNetworkAvailable=false、IdleSettings 不停止。
- Action：`pythonw.exe "<root>\trade_supervisor.py" --guard`，工作目录 root（无黑窗，日志写 live-data/_run_logs）。
- setup.py 回查任务清单已加入 QuantTradeGuard。
- 旧 QuantDailyTrade(onlogon)/QuantDailyNoon(13:05)/QuantDailyTradePM(15:10) 保留，经 daily_task 同样改调 --guard，作额外幂等唤醒。

## 五、事后补记命令（运维）

```bash
# 在项目根，用 venv python（Mac: api/venv/bin/python；Windows: venv\Scripts\python.exe）
python scripts/backfill_day.py --date 2026-10-09 --yes
# 多日按升序：--date 2026-10-09,2026-10-10（会校验交易日/连续性/幂等）
python scripts/backfill_day.py --date 2026-10-09 --yes --no-push   # 只落盘不上传
```
- 历史价来源 load_hist_klines：本地 etf_cache → akshare 东财 qfq → 新浪日K → 腾讯日K；最后一根日期必须等于补记日。
- 补记完成自动 `sync_live_data.py push --force "live data backfill <date> real close"`。
- 新浪日K 必须串行限速(≥1.2–2s)、Referer finance.sina.com.cn、直连(trust_env=False)、symbol 前缀只拼一次。
