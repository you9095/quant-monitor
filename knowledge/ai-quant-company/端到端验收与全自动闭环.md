| 系统 | 职责 | 动作 |

| macOS | 设计、开发、调试、测试、验收 | 立刻跑、立刻看效果、立刻改；跑通后 push GitHub |

## 全自动闭环（双击桌面"AI量化面板"）
`scripts/launch_panel.py --open` 六步：
1. 建立 GitHub 三通道连接（SSH22→SSH443→HTTPS）+ 更新代码（fetch + reset，更新后自动重启）；
2. 确保后台运行（未运行静默启动）；
3. 幂等补注册 QuantTradeGuard；
4. 成交守护 `trade_supervisor.py --guard`（盘中秒退、15:00 后按收盘价成交）；
5. 上传实盘数据；
6. 心跳 + 打开实盘面板。

计划任务 QuantTradeGuard（`scripts/win_self_register.py` 多级自愈）：
- 登录后 2 分钟起每 10 分钟（持续 1 天）；
- 工作日 15:00 起每 2 分钟（持续 30 分钟，收盘密集窗）；
- 工作日 15:30 起每 10 分钟（持续 2 小时兜底）；
- WakeToRun / StartWhenAvailable / 电池不阻止 / IgnoreNew；降级链 full→simple→minimal→命令行。

## 本轮修复的三个根因
1. **后端启动卡死**：launchd `ProcessType=Standard` 对守护进程 I/O 节流，read 信号文件被推迟；改 `Interactive` 后 6 秒 bind（plist 在 `~/Library`、不在仓库）。
2. **空仓现金漏算**：`live_aggregator.build_pnl_history` 加 forward-fill，补回无 daily 快照的空仓策略 20000 元。
3. **历史K线假重试**：`market_data.load_etf_close` 首次失败即 `return []`，改为真正重试 3 次、全失败才兜底旧缓存。

## 方法论（避免重蹈补丁循环）
- **先在 Mac 跑绿再交付**；Windows 只做运行，不做排障现场。
- 排障先做「手动进程 vs 守护进程」对照，快速定位 launchd I/O 节流。
- 核对「注释承诺 vs 实际调用」，勿因变量看似未使用而误判。
- 调试引擎走临时账本，勿写真 live-data；非交易时段跑出来的是前日价，污染即 `git restore` + 删未跟踪 daily、绝不 push。

## 红线（不变）
- 全程模拟盘 / 本机真实撮合，**绝不连接任何券商真实账号或资金账号**；
- 一切数据永久标注性质（模拟 / 实盘模拟 / 回测 / 事后补记 / UI 虚拟）；
- 模拟与实盘数据绝不相同；只有三源真实价全失败才不自动成交、亮红灯等人工。
