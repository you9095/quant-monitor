## 一、本次重构你需要掌握的核心技能

### 1.1 你需要学会做什么

作为代码开发执行人员，本次重构后，你需要掌握以下技能：

1. **快速定位代码**：修改某个板块时，30秒内找到所有相关代码
2. **按板块修改代码**：修改一个板块时，只修改该板块的代码，不影响其他板块
3. **新增板块**：按照规范新增一个板块
4. **删除板块**：按照规范删除一个板块
5. **移动板块**：按照规范调整板块顺序
6. **验证修改**：修改后用正确的方法验证

### 1.2 你需要遵守的铁律

1. **修改代码前先查板块注册表**：`config/modules.json`
2. **只修改对应板块的代码**：不要跨板块修改
3. **修改后必须验证**：不能只看代码，必须看实际效果
4. **修改前必须git备份**：出问题可以回滚
5. **不要直接替换原文件**：先输出到临时文件验证

### 2.2 如何使用注册表

当你需要修改某个板块时，按照以下步骤：

**第1步：打开注册表，找到对应板块**

```bash
cat config/modules.json | python3 -m json.tool
```

**第2步：查看该板块的配置**

每个板块包含以下字段：

| 字段 | 说明 | 用途 |
|------|------|------|
| `id` | 板块唯一ID | 对应HTML的id |
| `name` | 板块名称 | 快速识别 |
| `description` | 功能描述 | 了解板块用途 |
| `enabled` | 是否启用 | 控制显示/隐藏（目前仅文档用） |
| `order` | 显示顺序 | 控制板块顺序（目前仅文档用） |
| `html_element` | 对应HTML元素ID | 定位HTML代码 |
| `css_section` | 对应CSS分区 | 定位CSS代码 |
| `js_functions` | 对应JS函数列表 | 定位JS代码 |
| `backend_apis` | 对应后端API列表 | 定位后端代码 |

**第3步：根据配置定位代码**

例如，你要修改"策略卡板块"：

1. HTML：搜索 `id="module-strategy-cards"`
2. CSS：搜索 `板块: 03_策略卡板块`
3. JS：搜索 `renderStrategyCards`、`buildCardHtml` 等函数
4. 后端：搜索 `板块: 01_策略卡板块`

## 三、CSS代码组织与修改规范

```
/* ============================================================
   CSS板块目录

/* ========== CSS变量设计系统 ========== */

/* ============================================================

   ============================================================ */

   ============================================================ */
...

/* ============================================================
   板块: 03_策略卡板块
   ============================================================ */
...

...以此类推
```

### 3.2 修改CSS的正确步骤

**第1步：查注册表，找到对应CSS分区**

例如，修改策略卡样式 → CSS分区是 `03_策略卡板块`

**第2步：在CSS中搜索分区标记**

```
搜索：板块: 03_策略卡板块
```

**第3步：只修改该分区内的CSS**

不要修改其他分区的CSS，即使你觉得"顺便改一下"。

**第4步：浏览器截图验证**

修改后必须用浏览器截图对比，确认样式没有意外变化。

### 3.3 CSS修改铁律

1. **CSS顺序很重要**：后面的规则会覆盖前面的，不要随意调整CSS块的顺序
2. **不要跨分区修改**：只修改对应分区的CSS
3. **修改后必须截图验证**：不能只看代码
4. **新增CSS规则放在对应分区内**：不要随便找个地方放

### 4.2 修改JS的正确步骤

## 六、新增板块操作规范

### 6.1 新增板块的完整步骤

假设你要新增一个"市场情绪"板块：

**第1步：在板块注册表添加配置**

编辑 `config/modules.json`，在 `modules` 数组中添加：

```json
{
  "id": "module-market-sentiment",
  "name": "市场情绪板块",
  "description": "显示市场情绪指标",
  "enabled": true,
  "order": 11,
  "html_element": "module-market-sentiment",
  "css_section": "10_市场情绪板块",
  "js_functions": ["renderMarketSentiment"],
  "backend_apis": ["/api/v1/dashboard/market_sentiment"]
}
```

**第2步：在HTML中添加section**

在 `index.html` 中，找到合适的位置（比如策略日志板块后面），添加：

```html

     板块: 10_市场情绪板块 (module-market-sentiment)
     功能: 显示市场情绪指标

<section class="chart-section" id="module-market-sentiment">

      <span class="section-title">市场情绪</span>
    </div>

    </div>
  </div>
```

4. **必须完整验证**：前端+后端都要验证

## 七、删除板块操作规范

### 7.1 删除板块的完整步骤

假设你要删除"AB对比"板块：

**第1步：git备份**

```bash
git add -A
git commit -m "pre-delete-ab-comparison: 删除AB对比板块前备份"
```

**第2步：在注册表中禁用（不是删除）**

编辑 `config/modules.json`，把该板块的 `enabled` 改为 `false`：

```json
{
  "id": "module-ab-comparison",
  "enabled": false,
  ...
}
```

**注意：建议先禁用，观察几天，确认没有问题后再真正删除代码。**

**第3步：如果确认要删除，按以下顺序删除**

1. 删除HTML中的section
2. 删除CSS中的分区
3. 删除JS中的分区和函数
4. 删除后端中的分区和API
5. 从 `renderAll` 函数中移除调用
6. 从注册表中移除配置

**第4步：验证**

1. 浏览器打开页面，确认板块已删除，其他板块正常
2. 浏览器控制台，确认没有JS错误
3. 确认没有引用已删除的函数或API

### 7.2 删除板块铁律

1. **删除前必须git备份**：出问题可以回滚
2. **建议先禁用再删除**：观察几天，确认没有问题
3. **删除要彻底**：HTML、CSS、JS、后端、注册表都要删干净
4. **删除后必须验证**：确认没有引用已删除的代码

## 十、踩坑记录（必须学习）

### 10.1 坑1：CSS重构脚本把文件搞坏

**现象**：第一次运行CSS重构脚本，文件从3327行变成37行。

**原因**：正则表达式匹配style标签有问题。

**解决**：立即git回滚，重写脚本，先输出到临时文件验证。

**教训**：
- 永远不要直接替换原文件
- 先输出到临时文件，验证无误后再替换
- 运行脚本前必须git备份

### 10.2 坑2：后端重启后API返回空

**现象**：后端重启后，立即测试API，返回为空。

**原因**：后端还在启动中，API还没准备好。

**解决**：等待3秒后重试，API正常返回。

**教训**：
- 后端重启后必须等待3秒再测试
- 不要以为重启后立即就能用

### 10.3 坑3：移动JS函数引入时序问题

**现象**：（假设）移动JS函数后，某个功能偶尔不工作。

**原因**：全局变量初始化或事件绑定的顺序被打乱。

**解决**：不要移动JS函数，只添加分隔标记。

**教训**：
- JS函数不要轻易移动
- 时序问题很难排查，添加分隔标记就够了
