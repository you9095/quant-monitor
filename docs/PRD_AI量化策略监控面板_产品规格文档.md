## 一、产品概述

### 1.1 产品定位

一句话定位：**一个用真实市场行情，对 6 套量化 ETF/证券策略进行"每日模拟交易 + 全流程可视化监控"的本地化单用户面板。**

它不是实盘下单系统，也不是纯回测工具，而是介于两者之间的"**真实行情驱动的纸面交易（paper trading）监控台**"：

- **行情是真的**：每日通过东财/腾讯/新浪三个行情源拉取真实 K 线和实时价；
- **交易是模拟的**：不接券商、不下真单，按策略规则在真实价格上模拟成交；
- **账本是连续的**：每个策略从上线第一天起，累计盈亏逐日累加，形成一条不可篡改的实盘模拟净值曲线。

### 1.2 产品目标与核心 KPI

| 层级               | 目标            | 衡量方式                                                   |
| ---------------- | ------------- | ------------------------------------------------------ |
| **最高 KPI（不可妥协）** | 基于真实市场数据的模拟交易 | 每条数据 `data_source` 唯一为真实来源（work_logs），零随机数、零快照、零回测冒充实盘 |
| 一级目标             | 数据真实、连续、可追溯   | 交易日零缺口；累计盈亏三处自洽（work_logs / 信号 / 组合汇总）                 |
| 二级目标             | 策略表现一目了然      | 6 张策略卡 + 收益曲线，3 秒内看清每个策略今日动作与累计盈亏                      |
| 三级目标             | 异常能被主动发现      | 数据告警就地标注，异常发生当天即暴露，不靠人盯                                |
| 四级目标             | 板块可管理、可增删、可排序 | 板块注册表驱动，前端板块与代码区间一一对应                                  |

### 1.3 产品边界

**产品做什么：**

- 每个交易日拉取真实行情，按 6 套策略规则做模拟买卖决策与成交；
- 维护每个策略的持仓、现金、当日盈亏、累计盈亏、实盘天数；
- 展示策略卡、今日交易流程、收益曲线、回测/过拟合审计、风险指标、变更日志；
- 对数据异常进行自动检测和就地告警；
- 提供盘后复盘、买卖记录、对账单、盈亏历史等台账页面。

**产品不做什么：**

- ❌ 不接券商、不做真实下单、不碰真实资金；
- ❌ 不生成任何随机/模拟行情数据（永久禁用模拟模式）；
- ❌ 不用历史回测结果冒充每日实盘模拟结果；
- ❌ 不在数据缺失时用快照/前向填充/插值制造"每天都有数据"的假象；
- ❌ 不提供投资建议，面板数字仅为策略模拟结果。

### 1.4 名词术语表

| 术语                       | 含义                                                                        |
| ------------------------ | ------------------------------------------------------------------------- |
| 策略（Strategy）             | 一套完整的买卖规则，如追电、七星，每个有唯一 `sid`                                              |
| 实盘模拟 / live              | 用真实当日行情跑策略规则得到的模拟交易结果，区别于历史回测                                             |
| work_logs                | 每日引擎产出的最原始交易日志（`~/.hermes/work_logs/<sid>/`），是实盘数据的**唯一真实来源**             |
| 信号文件（signals）            | 由 work_logs 桥接/重建而来、供后端 API 读取的每日快照 JSON（`signals/<sid>_YYYY-MM-DD.json`） |
| 累计盈亏（live_total_pnl）     | 从策略上线首日起逐日盈亏累加值，单位元，**不可变历史账本**                                           |
| 累计收益率（live_total_return） | 累计盈亏 / 本金 × 100，**统一百分比**（如 151.42 表示 +151.42%）                           |
| 实盘天数（live_days）          | 策略已进行真实每日模拟的交易日数量                                                         |
| 今日动作（action）             | 当日策略信号：BUY 买入 / SELL 卖出 / HOLD 持有 / FLAT 空仓                               |
| 快照（snapshot）             | 把旧数据伪装成当日数据的行为，**永久禁止**                                                   |
| WFA                      | Walk-Forward Analysis，滚动前推分析，用于检验策略是否过拟合                                  |
| 棘轮（ratchet）              | 策略参数逐版本迭代优化的机制（如 R12→R17）                                                 |
| 会计恒等式                    | 现金 + 持仓市值 = 本金 + 累计盈亏，告警系统每日校验                                            |
| 三行情源                     | 东方财富 → 腾讯 → 新浪，按序容错的真实价格来源                                                |

## 二、用户与使用场景

### 2.1 目标用户

| 用户                  | 特征                            | 核心诉求                             |
| ------------------- | ----------------------------- | -------------------------------- |
| 主用户（策略主人，单人）        | 深度量化爱好者，熟悉 ETF、动量/轮动策略，有命令行能力 | 每天看盘后确认 6 个策略今天买卖了什么、赚亏多少、长期表现如何 |
| AI 运营/运维角色（袁言）      | 负责系统跑没跑、数据新不新                 | 确认 cron/守护任务正常、行情源可用、数据无断更       |
| AI 测试角色（程诗序）        | 负责数据真不真、改动有没有破坏旧数据            | 每次改动后跑真实性自检、回归基准                 |
| AI 技术/执行角色（陈以深/江予白） | 负责代码与架构                       | 按板块定位代码、安全修改、可回滚                 |

### 2.2 核心使用场景

1. **收盘后例行查看（最高频）**：打开面板 → 看顶部组合今日盈亏 → 扫 6 张卡的今日动作（买/卖/持有/空仓）→ 点开关心的策略卡看详情 → 看收益曲线对比。
2. **交易时段盯盘**：盘中打开"今日交易"区，看哪个策略触发了信号、目标标的是什么、等待开盘/收盘成交。
3. **复盘某次交易**：进入"买卖记录/对账单"，查某策略某一天的成交价格、数量、盈亏。
4. **评估策略质量**：看 WFA 过拟合审计、参数稳定性、A/B 对照，判断策略的高收益是真能力还是过拟合。
5. **异常排查**：看到卡片上红色告警标注 → 点进去看首次发现日期和原因 → 定位修复。
6. **移动端快速查看**：手机上打开 Tailscale 在线链接，看精简版卡片，需要时点"展开详情"。

### 2.3 用户旅程（收盘后例行）

```
打开面板
  → 顶部组合摘要（总资产/总收益/实盘起始日）
  → 今日交易·模拟盘（6 策略今日动作时间线）
  → 6 张策略卡（动作徽章 + 市值 + 累计盈亏 + 收益率）
      → 点击卡片顶部标签 → 弹出 8 段策略详情
  → 收益对比曲线（2Y / 5Y / 实盘 切换）
  → 每日盈亏趋势 / WFA / 参数稳定性 / A/B
  → 风险监控 / 策略变更日志
```

### 3.2 板块注册表机制（架构核心）

产品采用"**一个前端板块 = 注册表一条配置 = 一段 HTML + 一段 CSS + 一组 JS 函数 + 一组后端 API**"的一一对应设计。

- 配置文件：`config/modules.json`
- 每个板块字段：

| 字段                     | 说明                                |
| ---------------------- | --------------------------------- |
| `id`                   | 板块唯一标识（如 `module-strategy-cards`） |
| `name` / `description` | 板块名称与功能描述                         |
| `enabled`              | 是否启用（控制显隐）                        |
| `order`                | 板块排序权重（控制上下顺序）                    |
| `html_element`         | 对应 HTML 元素 id                     |
| `css_section`          | 在 CSS 文件中的代码分区名                   |
| `js_functions`         | 该板块依赖的 JS 函数清单（用于定位代码）            |
| `backend_apis`         | 该板块消费的后端接口清单                      |

- 全局设置：`allow_reorder`（允许排序）、`allow_toggle`（允许显隐）、`min_visible_modules: 3`（至少保留 3 个可见板块）。
- **产品价值**：板块的增加、删除、上下移动，都可以先在注册表定位，再精确改动对应代码区间，不跨板块误伤。

### 4.2 策略卡规格

每张策略卡是一个策略的"仪表盘"，自上而下包含：

| 区域            | 内容                                                | 交互                   |
| ------------- | ------------------------------------------------- | -------------------- |
| **顶部标签（可点击）** | 版本名（如 R17_score_max_38）、数据期（2024-06~2026-06）、口径摘要 | **点击弹出策略详情弹窗（规则 6）** |
| 状态徽章          | 运行中（绿）/ 未启动（灰）/ 告警（红/黄）                           | 告警态就地标注异常类型 + 首次发现日期 |
| 今日动作          | BUY/SELL/HOLD/FLAT + 目标标的代码（如"观望 513520"）         | —                    |
| 核心指标          | 当前市值、总盈亏、收益率（%）、今日盈亏、实盘天数                         | 收益率统一百分比、保留 2 位小数    |
| 迷你曲线          | 该策略实盘净值小图（可开关/点开大图）                               | 点击放大                 |
| 仓位现金          | 持仓明细、可用现金                                         | 空仓时显示"空仓观望"          |


**卡片数据口径（强约束）：**

- 当前市值 = 初始本金（10,000）+ 累计盈亏；
- 收益率 = 累计盈亏 / 10,000 × 100%，百分比格式；
- 空仓且无持仓时，持仓市值为 0，现金应等于当前市值（会计恒等式，见 §10）；
- 卡片数字来自 `/api/v1/dashboard/overview`，经前端 `transformApiData` 转换，**禁止用 mockData 写死任何真实指标位**。

### 4.3 策略详情弹窗规格（8 段，纯文字纵向排列）

点击卡片顶部标签弹出，**纯文字、从上到下、每个属性占一行**，完整呈现 8 段策略详情（数据来自 `strategies.json` 的 `caliber_full`，以" · "分隔 8 段）：

1. **版本名称**：策略版本号与命名（如追电 R17_score_max_38 / R39_bear_filter）；
2. **标的筛选**：标的池范围、数量、筛选/排序规则、过滤条件；
3. **买入规则**：触发买入的量化条件；
4. **卖出规则**：触发卖出的量化条件；
5. **止盈止损**：硬止损、移动止盈、回撤约束、成交制度（T+1、手续费）；
6. **牛熊针对**：是否启用熊市过滤、跨周期回测验证；
7. **回测数据**：2Y/5Y 年化、夏普、最大回撤、胜率、交易笔数（明确标注"回测"口径）；
8. **其他特点**：本金 setcash、持仓数、权重、基线说明等。

弹窗还须包含实盘模拟核心指标区（市值/累计盈亏/收益率/今日盈亏/实盘天数）、仓位与现金、持仓明细、回测绩效。  
**禁止**：弹窗"--"占满全屏、点击无反应、JS 报错不弹出（规则 6）。

### 4.4 各策略口径（摘自 strategies.json，弹窗 8 段数据源）

- **七星 R120**：11 ETF K 线动量评分；买入 breadth≥0.353 且持仓数=1；卖出 breadth<0.353 或池相关矩阵任一相关>0.6 降权；2Y 回撤硬约束≤-20%、T+1、含费；R122 跨周期抗跌（2022-2023）。
- **三驾马车 R35_biweekly**：100 ETF 池去重、群聚因子 top_n 按成交量选 5；动量+宽度+止损三策略并行 AC，半月调仓；任一策略触发卖出则整体仓位减半；周频替换成本<0.1% 才 ACCEPT；5 只等权。
- **追电 R17/R39**：11 ETF 跨大类、score_max=38 排序、R²≥0.5 过滤；加权线性回归动量（LinearRegression close 3 coef）上穿阈值且 score 前 38 买入；动量回归系数<0 或 R²<0.5 卖出；硬止损 -10% + 移动止盈；5Y 段启用熊市过滤 R39，2Y 不启用。
- **三合 R25_vol_weight**：5 ETF + 小市值/ETF 动量/一致性风控三源融合；三源信号投票 R26、源信号去冗余防同向加杠杆；任一源卖出或一致性跌破阈值即卖；波动率倒数加权 + 熊市过滤；周度调仓。

### 8.3 累计账本规则（不可变）

- 今日累计盈亏 = **上一交易日累计盈亏 + 今日盈亏**（时间序列积分，不是可独立设置的标量）；
- 昨日累计必须从上一交易日信号/work_logs 读取，**禁止从零重算**；
- 今日盈亏缺失或不可信 → 保持上一交易日累计值不变，不用 0 或随机数替代；
- 批量回填历史必须：备份全部信号 → 用"当前上线参数 + 固定 1 万本金 + 真实历史 K 线"经 `daily_runner_v2.py --date D --skip-fetch` 重跑 → 全量重建信号 → 校验"每日盈亏累计末值 == live_curves 末值 − 1 万本金"。

## 九、行情源与成交规则（2026-10-10 用户权威增补）

### 9.1 三源容错

行情获取顺序：**东方财富 → 腾讯 → 新浪**。三源全部失败才判定拿不到真实价。

### 9.2 成交规则（最高优先）

1. **唯一禁止自动成交/补单的条件**：东财→腾讯→新浪三源全部失败、拿不到当日真实价；
2. 只要任一源拿得到当日真实价（盘中实时价或收盘后收盘价），**就必须成交/补成交**。A股 15:00 收盘后现价即当日收盘价，下午、傍晚都可补当日成交，**不存在"17:00 后不补单"的截止线**；
3. 行情失败按约 10 分钟持续重试（前几轮 2/3/5 分钟退避，之后固定 10 分钟），循环直到拿到真实价；**绝不用旧价、绝不伪造、绝不直接判定当日不成交**；
4. 跨日发现漏单：取得到漏单日真实收盘价（历史日 K）就自动按该真实收盘价补记，并标注"事后补记"；只有连历史真实收盘价都三源全失败才亮红灯、常亮、等人工；
5. 调度以每 10 分钟幂等周期守护 `trade_supervisor.py --guard` 为准；非交易日/上午/已成交/红标均秒退，不长驻、不 7×24 成交。

## 十、数据告警系统

### 10.1 设计原则：就地标注

**哪个位置的数据出错，就在那个位置直接标注**，而非另开告警页：

- 错误（error）：红色背景 + ❌ + 首次发现日期（MM-DD）；
- 警告（warning）：黄色背景 + ⚠️ + 首次发现日期；
- 鼠标悬停显示完整异常描述与首次发现日期；呼吸闪烁吸引注意；
- **异常不修复，标注不取消**；修复并复检通过后自动消失。

### 10.2 告警类型

| 类型                    | 监控字段        | 级别      | 触发条件                      |
| --------------------- | ----------- | ------- | ------------------------- |
| `accounting_identity` | 现金/持仓/本金/累计 | error   | 会计恒等式不成立：现金+持仓 ≠ 本金+累计盈亏  |
| `capital_mismatch`    | 本金          | error   | 本金与标准值（10,000）不一致         |
| `zero_pnl`            | 累计盈亏        | warning | 累计盈亏异常为 0（市值贴近本金）         |
| `stale_signal`        | signal_date | warning | 信号文件陈旧超过 5 天              |
| `negative_cash`       | cash        | error   | 现金为负                      |
| `simulated_data`      | data_source | error   | 数据源含 simulated/模拟（最高级 P0） |
| `missing_signal`      | 信号文件        | error   | 当日信号文件不存在                 |

### 10.3 生命周期与状态

- 状态文件：`data/alerts_state.json`；引擎：`api/data_alert_engine.py`；
- 新异常：`first_seen=今天、last_seen=今天`；持续异常：保留 first_seen、更新 last_seen；已修复：从状态文件移除、前端标注取消；
- 手动运行：`python3 api/data_alert_engine.py`；
- 监控覆盖对象：**全部 6 个策略**，逐个扫描，不是只监控单一策略。

### 10.4 会计恒等式（核心校验）

```
现金 + 持仓市值 = 初始本金 + 累计盈亏
```

任一策略该等式不成立即报 `accounting_identity`，并给出各项数值与差异额，直接标注在该策略卡盈亏区。

## 十二、产品铁律与约束（不可妥协）

> 完整原文见 `PROJECT_RULES.md`，效力高于一切 Skill、历史注释和 Agent 自主判断。

1. **策略 .py 核心文件保护**：只有强烈针对性才允许改，改前须指明行号、预期影响并取得用户许可；禁止批量格式化/重命名/"顺手优化"。
2. **永久禁用模拟模式**：禁止 random 随机盈亏、禁止 simulated 数据源、禁止任何异常下降级到假数据、禁止 mock 填真实指标位；异常时正确做法是报错停止/用缓存并标注陈旧/保持上日数据。
3. **收益率统一百分比**：如 270.31 表示 +270.31%，禁止小数形式；前端 +270.31% 保留 2 位。
4. **展示与计算逻辑与历史一致**：字段名、含义、口径、单位、精度、累计方式一经确定不得中途更改；更改须说明原因、历史影响、迁移方案并获许可。
5. **不覆盖历史累计数据**：累计字段是历史账本，覆盖=销毁历史；每日"上日累计+今日盈亏"，批量重建须备份+许可。
6. **策略卡弹窗必须可用**：点击顶部标签弹出完整详情，不得"--"占屏、无反应、JS 报错。
7. **快照永久禁止 · 回测/实盘严格分离 · 未启动留空 · 交易日连续**：
   - 禁止快照/前向填充/插值/信号回退/历史信号冒充当日；没真实数据就留空；
   - 回测只服务参数迭代，实盘只来自每日调度，二者不得互相填充；
   - `live_days==0` 策略灰色"未启动"、实盘位全 0、不计入组合；
   - 交易日历以 `~/qixing_data/etf_kline/510300.csv` 为准，work_logs 须零缺口、零 0 字节、周末不误跑；
   - 每次改动后跑真实性自检（active_count 口径、data_source 唯一、交易日零缺口、累计末值三处自洽、双端截图）。

**违规处理**：违反规则 2、5、7 为最高级 P0 事故，立即停止、回滚、根因复盘，记录到 `POSTMORTEM_*.md` 与工作日志。
